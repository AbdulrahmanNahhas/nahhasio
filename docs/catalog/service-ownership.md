# Schema service ownership

[Documentation index](../README.md) · [Database ownership](database.md) · [Migration baseline](migration-baseline.md)

The schema/API/CLI transition is implemented in the shared Rust catalog services. Historical
phase plans and test receipts are retained in Git. The sole active schema history is the
[current baseline](migration-baseline.md) plus future additive migrations; this is not another migration plan.
See [DATABASE](database.md) for data ownership and [DEVELOPMENT](../development/getting-started.md) for current tools.

Installed acceptance is recorded in the [family-server handoff](../operations/family-server.md).
Stored-file playback and reviewed imports have a managed-media service. Video-derived stills
have separate scope. Read the table below as a source-level map.

## Feature ownership and exposure

Generic schema visibility and bounded table reads are available through inspection. Feature-specific
read, write and enforcement support vary. Keep credentials and private rows out of projections.
When reviewing possible removals, check schema constraints, runtime SQL, profile activity, admin
inspection, generic CLI access, recovery tools and actual retained data before proposing a migration.
