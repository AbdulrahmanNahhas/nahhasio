# Nahhasio 0.2.0-rc.1

[Release notes index](README.md) · [Deployment procedure](../operations/deployment.md) · [Operations runbook](../operations/runbook.md)

This is a release candidate, not an Alpha-channel update. Its signed server feed is `nahhasio-rc`,
its Flatpak branch is `rc`, and its client repository is `/flatpak-rc/`. Do not replace the Alpha
feed or `/flatpak/` when publishing an RC. Branch changes are deliberate and must preserve private
application state.

## What changed

- Direct stored-media delivery replaces Jellyfin. The native client plays authorized originals;
  a separate rootless worker handles reviewed media imports and server acquisition jobs.
- Device and server downloads, saved catalog snapshots, and playback remain independent.
- Server maintenance separates compatible updates from reviewed schema upgrades. The staged
  upgrade verifies a restored database before switching and retains the previous database for recovery.
- Backup scheduling and retention use host-owned operations. Flatpak or the desktop Software
  manager still owns client updates.

## Upgrade boundary

An older 0.1.3 API cannot run the new schema-maintenance operations. Use the matching signed
host-tool bootstrap and prepare the managed media root before enrolling an eligible installation.
Follow the [maintenance runbook](../operations/runbook.md#receiving-updates-from-the-app) and keep a
verified recovery copy. An RC client install alone does not enable the server-side features.
