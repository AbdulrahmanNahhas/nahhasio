# Nahhasio 0.2.0

[Release notes index](README.md) · [Deployment](../operations/deployment.md) · [Operations](../operations/runbook.md)

**Source preparation.** This is the first numbered release after the historical `0.2.0-rc.1`
cutover. New releases are reviewed as drafts and use the same numbered update feed (`nahhasio-alpha`)
and Flatpak branch (`alpha`). Existing numbered installations already follow that feed. Keep the
RC artifacts for recovery; do not publish future releases to the RC feed.

## Catalog experience

Home now has linked section headings, RTL arrow navigation, artwork-led planets, and discovery
shelves for awards, studios, and people. Work cards display color-coded scores out of 100.
The Planets directory shares Home's landscape tiles. Music and trailers open on Music by default
and use compact track-style cards, with a music icon in navigation.

Awards now has its own directory and award archives with year-by-year winners and nominees.
Work details and episode browsing were redesigned in source, with release selection, context
and episode actions described in the [Work page guide](../desktop/behavior.md#work-page-details).
Airing and release handling is a [0.2.1 candidate](../project/roadmap.md#02x-follow-ups).

## Watch and playback

- Watch places source selection and episode navigation below the video and keeps the work and
  season ratings beside the episode title. The source menu offers anime dub and subtitle choices,
  while the adjacent next-source button advances through the ranked providers.
- The loopback browser preview supports embedded playback, direct HTTPS video and linked home
  videos. Its completion tracking uses the server's 90% threshold for a confirmed episode.
  The Linux app owns torrent playback and device downloads. See [Streaming](../desktop/streaming.md)
  for source priority and provider limits.

## Backend hardening

- Expired media jobs now reach a durable terminal state even when there is nothing else to run.
- Uploads check available storage without starting a subprocess per chunk; the existing 5 GiB
  reserve and durable offset acknowledgement are unchanged.
- Cancelling an artwork request no longer releases its resize slot before the blocking task stops.
- Browse reuses the same prepared SQL text across pages of a given query shape. The facets query
  no longer materializes card payloads or computes page-only fields. Sorting, grouping, response
  fields and schema are unchanged.

In a local PostgreSQL 17.11 comparison against `5f2c0db` (1,500 synthetic works and 18,000 episodes),
facet responses were identical. Median `EXPLAIN ANALYZE` execution time over five warm samples per
variant changed from 440 to 135 ms for public works, and from 380 to 127 ms for admin installments.
These are fixture SQL timings, not production latency. Measure mixed Browse, artwork, ranges, and
uploads separately before changing indexes or drawing conclusions about installed performance.

## One-time transition from RC

Only after the signed release and its Flatpak repository are published, use the procedures below.
Take and verify an independent backup before the cutover. Perform the host steps as the installation
owner, using the selected config root and the independently verified installer bundle described in
[host-tool delivery](../../packaging/operations/README.md#coordinated-host-tool-delivery-011-onward).

1. Wait for current maintenance to finish. If the automatic update timer is active, stop it during
   the cutover. Stop **only** `nahhasio-maintenance.service`; the server can stay running during the
   feed switch. From the extracted, verified 0.2.0 installer bundle, run:

   ```sh
   python3 packaging/operations/operations.py --config-root "$HOME/Nahhasio/config" switch-to-numbered-feed
   ```

   Restart `nahhasio-maintenance.service` even if the command refuses the switch. It verifies a
   signed, newer numbered release and changes only the feed URL. It does not install the image,
   activate host tools, change the database, or replace publisher trust. Custom feeds are not
   switched automatically.

2. In **Server maintenance → Updates**, check for updates and choose **Backup and update server**.
   Confirm the action. The worker verifies the release, creates its own recovery backup, activates
   the signed image and tools, and checks readiness. If the schema fingerprint changes, review
   and confirm the exact version instead; the worker stages and verifies a separate restored
   database before switching. Reconnect to read the job result. Restore the prior timer policy only
   when the new installation is ready.
3. Close the RC desktop application. Install `alpha` from the signed numbered feed using the
   [Flatpak install procedure](../../packaging/flatpak/README.md#install-and-update). If the trusted
   `nahhasio-alpha` remote is already configured, use `flatpak install --user nahhasio-alpha
   io.nahhasio.Linux//alpha` (or update that ref if already installed). Select `alpha` with
   `flatpak make-current --user io.nahhasio.Linux alpha` and launch it explicitly with
   `flatpak run --branch=alpha io.nahhasio.Linux`. Keep the RC ref until the new version is verified;
   never delete shared application data as part of the branch switch.

## After the transition

- **Backup now**, scheduling, and reviewed restore stay under Server maintenance → Backups.
  Compatible server updates include a backup automatically; restore and schema changes retain
  explicit confirmation. PostgreSQL major upgrades remain separate.
- **Check and install app update** requests an update of the running Flatpak through its own portal.
  Keep the app open, then relaunch if it reports a staged update. If the portal is unavailable or
  the update requires new permissions, use the adjacent Software action. The server and this
  device have separate update results.

Local tests and a successful build do not establish signed release publication, an installed
portal update, Fedora/Podman switching, physical playback, or reboot behavior. Use the
[verification guide](../development/testing.md) before installing on the family PC.
